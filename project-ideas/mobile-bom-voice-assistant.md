# 手机端语音交互式焊接助手（点子整理）

> 2026-10-07 Efold 口述整理。单独立项，暂缓。现状：无现成"一键转手机适配 BOM"工具；InteractiveHtmlBom（MIT）最接近但桌面 UI 手机难用。
> → 2026-10-08 高思考重做版方案（当前唯一有效）见 [docs/plan.md](../docs/plan.md)（硬约束：上卡片/点位图、下三大按钮、TTS 保留、ASR 暂缓；plan-v1.md 已废弃留档）。

## 核心场景
手焊时手机放手边，全程语音交互，不用动手翻 BOM 表。

## 设计原则
1. **小屏渐进展示**：手机屏幕小，一次只展示当前器件，不堆全表。
2. **语音为主**：播报 + 语音指令，解放双手和眼睛。都到手机端了还要一个个划着看位号，就没优势了。
3. **按取料顺序报菜名**：焊接顺序跟着实际取料顺序走（元件袋/料盘的摆放顺序），而不是按位号乱找。
4. **底部大按钮可盲点**（2026-10-07 补充）：底部主按钮（"好了/下一个"）要做得够大，一手拿镊子时用指关节也能准确点中——它是噪音环境下语音失效时的主兜底交互。

## 功能点

### 1. 渐进式展示
- 一次只显示一张"当前器件"卡片：封装 + 器件 + 值。
- 不报位号（R37、C112 这种没人会去记）。

### 2. 语音播报与指令
- 播报下一个，例如："下一个，0603 电阻 10k，板子左上角"。
- 焊好后说"好了"（或指定指示音/口令）→ 自动推进到下一个。
- 需要：重复、跳过、回退等基本指令。
- 实现可选大模型：规则引擎更快更稳；接大模型自然语言更灵活，但速度慢。

### 3. 焊接顺序规划（报菜名）
- 输入取料顺序：用户告知元件袋从上到下分别是什么，或拍一张"元件墙"照片自动识别。
- 输出按取料顺序排好的焊接序列，逐个播报。
- 每个器件播报时附带它在板子上的大概方位。

### 4. 朝向标定
- 开工前先确定板子摆放朝向（是不是正着放），否则"左上角"这类方位描述无意义。

## 全流程梳理 + 摩擦点复盘（2026-10-07 老莫视角）

### ① 导入解析
- 输入嘉立创/KiCad 工程 → BOM + 位号坐标/封装/层。
- **落**：嘉立创格式逆向（jlc-kicad-bridge 今晚项目）；文件怎么到手机（一键转的入口：电脑传文件？嘉立创云端直接拉？）。
- **摩擦**：嘉立创标准版/专业版格式不同；KiCad 各版本差异。

### ② 焊接顺序规划
- 输入取料顺序：手动/语音录入元件袋顺序，或元件墙拍照识别 → 生成焊接序列。
- **落**：拍照识别的 fallback（袋子反光、手写标签识别率低时怎么办）；通用料（整袋 10k 电阻）怎么处理。
- **摩擦**：取料顺序 ≠ 最优焊接顺序。工艺约束（先小后大、先矮后高、先贴片后插件、双面板先焊哪面）会和取料顺序打架，两套顺序要融合，不能只按取料走。

### ③ 朝向标定
- 开工确认板子朝向，否则方位描述无意义。
- **落**：标定方式（拍照自动识别 vs 口头确认）；焊接中途翻板/旋转后必须重新标定（说"翻面了"触发？）。
- **摩擦**："左上角"在板子转了之后就错了；地标式描述（"USB 口旁边那颗"）更鲁棒。

### ④ 焊接循环（语音）
- 播报 → 焊 → "好了" → 下一个。
- **落**：噪音环境（热风枪/赛场嘈杂）下语音指令的备选方案（底部大按钮——持镊子用指关节点、音量键、蓝牙遥控器）。
- **摩擦**：10 个同样的 0603 没必要每个都念一遍，要批量模式（"下面 10 个都是 100nF，位置标出来了"）；小屏上点位图缩放找具体位置的交互；焊错/跳过/返工时的状态回退（"刚才那个歪了，重来"）。

### ⑤ 收尾检查
- **落**：漏焊清单——说了"好了"不等于真焊好，至少保证没有漏掉的；双面板第二面的流程衔接。
