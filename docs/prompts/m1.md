# M1 执行 Prompt —— webapp 核心循环（能开焊的最小产品）

> 给未来的我：本文件自足。开工先读 `docs/plan.md` §2、§3、§5、§6、§9、§11 与 `docs/stj-spec.md`，再读本文件。
> 总则：验收 = 真跑命令 + 截图/录屏留档；没跑过不许说完成；QQ/NapCat 汇报一律纯英文 ASCII。
> 前置检查：`git tag -l m0-done` 存在；`node -v` ≥18。与 M2 可并行（两阶段互不触碰）。

## 目标

把演示任务变成能真焊的产品：导入 → 焊接循环（卡片 + 三按钮 + TTS + 跳过 + 返工/撤销）→ IndexedDB 断点续焊 → 极简总结；深色 + WakeLock。阶段末完成**第一次真机验证**（TTS 音色/延迟、按钮手感、常亮）——这是全项目最大风险的暴露点。

## 输入文件

- `docs/plan.md`、`docs/stj-spec.md`（M0 冻结版）
- `webapp/public/demo/demo.stj.json`、`tools/check_demo.py`（导入统计核对基准）

## 范围内（全部要做）

- 脚手架：Vite + Preact + TypeScript + vite-plugin-pwa；`src/{loader,planner,runner,speaker,store,dispatcher}/`（`boardmap/` 本阶段不建）。
- 8 屏先做 4：首页任务库 / 导入（文件选择 + 「粘贴 JSON」应急入口 + 导入统计确认页）/ 焊接循环 / 极简总结屏（总颗数 + 用时 + 跳过数文字）。
- loader：STJ v1 的 TS 校验（规则与 M0 validator 一致），统计 = 颗/组/极性/来源。
- planner（纯函数）：消费 `group_order_default` + 组内蛇形扫描（按 y 分带、带内 x 蛇形）。
- runner：plan §2 状态机全语义——完成 / 上一个短按（指针 -1、状态不变；队首则无效 + 短震）/ 上一个长按 600ms（双段震动确认，清回待焊）/ 重新播报（按钮或点卡片）/ 卡片上滑跳过。§2.2 两条返工走查是指定测试用例。
- dispatcher：唯一指令入口，按钮与手势只发指令（为日后 ASR/蓝牙键留位）。
- speaker：speechSynthesis 封装；播报前 `cancel()`；utterance 进组时预构建；`voiceschanged` 异步就绪；iOS 手势解锁挂在「开始焊接」按钮；默认语速 0.9×。句模板 = 普通颗（无地标省略后半句、极性追加「注意极性」）+ 收工简句；TTS 完全不可用 → WebAudio 提示音 + 震动兜底，流程照跑。批量组本阶段一律逐颗完整播报。
- store：IndexedDB 每次操作后原子写（状态 + 时间戳）；首页多板卡片（进度条 / 重置进度 / 导出 STJ / 删除）。
- UI 按 plan §5 定死稿：上 ~60% 大区本阶段 = 卡片全宽（缩略图区不出现，第三行方位留空）；下控制区三按钮 1fr/1fr/2fr，完成占一半宽、高 ≥ 屏高 1/8、间隙 ≥10dp、热区超出视觉边界、按压缩放变色 + 震动 30ms；顶部细进度条 + 「第 x/N 颗」 + ⚠极性角标；默认深色主题。
- WakeLock + `visibilitychange` 补申请 + 进入循环可选全屏。

## 验收标准（真跑真验，证据进 `docs/qa/m1/`）

1. `npm run build` 成功；`npm run test`（vitest）全绿。必测：planner 蛇形序（含跨行回绕样例）；dispatcher 全操作语义（§2.2 返工走查 + 误按撤销 + 队首短按无效，断言完整状态序列）；loader 拒收坏 STJ（覆盖 M0 三类坏样例场景的 TS 版）；speaker 拼句（mock speechSynthesis）。
2. 浏览器自动化（ZCode browser-use，对 build 产物本地服务）一镜到底并逐步截图：内置演示任务 → 推进 3 颗（断言卡片「第 4/12」）→ 短按上一个（回第 3 颗、状态不变）→ 完成（到第 4 颗）→ 长按上一个（第 3 颗清回待焊，进度数字断言）→ 上滑跳过 1 颗 → **刷新页面，断言指针/各单元状态还原** → 焊完全部 → 总结屏。截图存 `docs/qa/m1/smoke-*.png`（上滑允许 JS 注入 touch 事件）。
3. 导入真验：走「导入」流程选 demo 文件，统计确认页数字与 `python tools/check_demo.py` 输出一致（截图对照）。
4. PWA 真验：DevTools Application 面板无错误（截图）；**Offline 模式 reload 后核心循环可继续用**（截图）。
5. 真机清单 `docs/qa/m1/device.md` 逐项打勾并附证据：中文 TTS 音色试听（录音/录屏文件）；按下「完成」→ 出声延迟（录屏读帧，要求无排队积压、体感跟手）；三按钮指关节盲点测试（记录误触次数）；10 分钟常亮；焊接中杀进程重开恢复到原指针；深色对比度肉眼可读。无真机时自动化项先行，真机清单标注「阻塞待机」。
6. `git tag m1-done`。
