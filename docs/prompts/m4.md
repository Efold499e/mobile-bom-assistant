## 范围内

- 报菜名屏：按默认序列出全部 group 芯片（值 + 数量 + 封装）→ 点选即取料序、再点取消 → 或一键「用默认顺序」；不做拖拽。**点选序持久化进任务状态**（断点恢复必须还原用户的排序，而不是退回默认序）。
- 收尾清单：队列耗尽 → 列出全部未完成与已跳过（带点位标记）→「开始补焊」以这些单元建临时队列、复用现有循环 → 全清后进总结。
- 双面衔接：一面焊完 →「翻面继续」→ 左右翻/上下翻确认 + 地标核对 → 重标定 → 下一面（镜像渲染 M3 已有，本阶段接流程）；单面任务不出现此步。
- 设置屏（⚙ 首页出现）：语速 0.7–1.2×（默认 0.9）；TTS 体检（发声测试 / 可用 voice 列表 / 缺中文离线包时的提示文案）；批量阈值（默认 4，可关闭）。设置持久化。
- 总结屏完整化：总颗数 / 用时 / 各面完成度；收尾与翻面句模板按 §6 补齐。

## 验收标准（真跑真验，证据进 `docs/qa/m4/`）

1. `npm run test` 全绿，新增必测：点选序 → 运行队列生成（断言与点选顺序一致）；断点恢复还原点选序（持久化往返）；补焊临时队列语义（收尾 → 补焊 → 全清状态机，断言未新增 dispatcher 指令）；设置读写往返。
2. 浏览器自动化场景 + 截图 `docs/qa/m4/*.png`：
   a. 报菜名以「A、C、B」点选序重排后开焊，首颗卡片属于 A 组（断言 + 截图）；刷新后排序保持；
   b. 跳过 2 颗后焊完 → 收尾清单恰好 2 项且带点位标记 → 补焊 → 全清 → 总结（用时 >0、各面 100%）；
   c. 双面演示任务焊完第一面 → 翻面确认选「左右翻」→ 标定屏 → 第二面首颗 side=bottom 且地图为镜像；
   d. 批量阈值改 6 → demo 中 qty=4 的组不再触发询问（断言）；关闭批量 → 全程逐颗完整播报。
3. 真机清单 `docs/qa/m4/device.md`：TTS 体检全流程（含无离线包时的提示截图）；语速 0.7 / 1.2 听感；真机翻面 + 重标一次走通；报菜名照袋点菜实测（真实元件袋摆 5 组演练）。无真机则标注阻塞待机。
4. `npm run build` 成功；webapp 与 converter 两套测试全绿。
5. `git tag m4-done`。
