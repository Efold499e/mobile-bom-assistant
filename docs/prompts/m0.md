## spec 冻结时必须裁定的开放点（每条以「裁定 + 一句理由」写进 stj-spec.md）

- qty 一致性：qty 必须同时等于该组 refdes 数和该组 placements 数（plan §4 示例 qty=7/refdes=3 视为示例截断；validator 强制检查）。
- `bbox_mm` 可选：缺省时按封装名推默认尺寸，推不出用 1.0×1.0mm 占位。
- `rot_deg` 约定：查证 KiCad 的角度约定后写死取值范围与旋转方向。
- 双面铁律：底面件一律存顶视图坐标 + `side:"bottom"`，转换/存储环节禁止镜像；镜像只发生在手机端渲染（spec 写死，M2 出单测）。
- speak 回退：无 `value_speak`/`footprint_speak` 时，播报端回退念 `value`/`footprint` 原文。
- outline：≥3 点多边形；坐标单位 mm；原点 = 板框左上、y 向下；小数位数上限写死。
- `sides` 枚举 {top, bottom}；`landmarks` ≤3 个。
- 兼容规则：format/version 严格匹配；未知字段忽略（向前兼容）。

## 演示任务必须覆盖的要素

恰好 12 颗 placements；groups ≥4；存在 qty≥4 的批量组；极性件 ≥2；`side:"bottom"` 的 placement ≥2；landmarks ≥1（speak 用中文名，如「Type-C 座」）；outline 用非四点矩形多边形；`group_order_default` 手工排好且满足「单面焊完再另一面、先小后大」。

## 验收标准（逐条真跑）

1. `git log --oneline` ≥1 条；`git tag` 含 `m0-stj-v1-frozen`。
2. `python tools/validate_stj.py webapp/public/demo/demo.stj.json` 退出码 0，统计行数字与 stj-spec.md 附录声明的完全一致（输出留档）。
3. `python tools/check_demo.py` 退出码 0，脚本内断言上述「演示任务必须覆盖的要素」全部成立（逐项可数）。
4. 负路径：造 3 个坏样例 `docs/qa/m0/bad-version.json`、`bad-missing.json`、`bad-dangling-gid.json`，validate 对每个退出码均非 0（输出留档）。
5. `grep -rnE "^\s*(import|from)\s+" tools/` 只出现 Python 标准库模块名。
6. `docs/qa/m0-report.md` 汇总以上全部命令输出；打 `git tag m0-done`。
