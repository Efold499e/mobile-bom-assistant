# M2 契约备注（只记录，不改动 —— 留 M5 后统一裁处）

> 2026-10-12，bom2task 落地过程中发现的 STJ v1 / 校验器缺口。按 m2.md 边界要求，
> 本文只记录，不改 `docs/stj-spec.md`、`tools/validate_stj.py`、`demo.stj.json`。

## 1. 跨面组（同一袋子出现在两个面）

STJ 分组键 = (kind, footprint, value)，不含 side —— 同值同封装在顶/底面各有一部分时，
它们必然同组。group_order_default 的"单面焊完再另一面"排序把这种组归入 top 段
（`_side = top if any member top`），意味着组内底面成员会在翻面前被排进队列。
手机端 planner（M1 蛇形）不感知面切换，会按队列顺序直接焊底面件。
**v1 实际影响**：真实板子同值同封装跨面极罕见；出现了也只是顺序不优，不会漏焊。
**建议**：M5 实战若真的遇到，再讨论 spec v1.1（组键加 side 或队列内隐式分面）。

## 2. 嘉立创底面旋转角映射未经真实文件实证

bottom 件 `rot' = (180 - rot) mod 360`、top 件 `rot' = (360 - rot) mod 360`
沿用 JLC2KiCad 社区约定（m0-report 契约疑点 #2 已预告）。fixtures 自造，
**没有真实嘉立创双面 CSV 对验证过**——列入 M5 开工门禁材料清单（真实 KiCad 工程 +
嘉立创 CSV 对），拿到后先跑转换 → 手机端点位图与实物比对再焊。

## 3. 极性推断为"宁滥勿缺"口径

LED / 二极管 / 全部 IC 一律 polarity:true（plan §10"IC pin1"的保守解读）。
某些无方向 IC（如 0201 空阻？不，ic 类如无 pin1 标记的 LDO）也会带极性警示，
播报多一句"注意极性"。宁可多说，不说错的；M5 实战后按误报率决定是否细化。

## 4. 校验器未拦截的可疑形态（记录，不算缺陷）

- `bbox_mm` 长宽比异常（如 0.6 × 3.0 的竖装 LED）合法——旋转后焊盘分布本来就会这样；
- footprint 展示名取"首个命中的常见尺寸码"（如 `LED_0805_2012Metric` → `0805`），
  同一块真实 PCB 上极少数封装可能不含任何已知码而落到原始名（如 `USB_C_Receptacle`）
  ——只影响卡片第二行文案与跨源分组一致性，不影响焊接流程。

## 5. iBOM 旋转角符号

pcbdata.json 的 rotation 按原值透传（假定其与 KiCad 同为顶视图逆时针）。
iBOM 导出来源本身是 KiCad，故约定一致的概率高，但与 #2 同样未经真实导出文件实证。
