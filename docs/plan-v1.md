## 0. 一句话定位

把一块板的焊接任务变成一条按你取料顺序排好的流水线。手机上一次只干一件事：**看当前件 → 焊 → 按大按钮**。耳朵听播报，眼睛只看卡片和板子，双手不离镊子和烙铁。

## 1. 硬约束（本方案的地基）

1. **布局定死**：上方大区域（约 60% 屏高）放当前器件卡片 + 点位图；下方控制区固定三个大按钮：完成（主）/ 上一个 / 重新播报。
2. **按钮可盲点**：一手持镊子时指关节能准确点中——完成按钮占半行宽、高度 ≥ 屏高 1/8、按下有震动 + 视觉反馈、按钮间留误触死区（≥8dp 间隙 + 按钮做超出视觉边界的热区）。
3. **TTS 是主信息通道**；语音识别整体暂缓（不做 ASR、不做关键词唤醒），控制全靠按钮 + 手势。但所有输入收口到统一的指令分发器，日后接 ASR 只是加一个"指令来源"，零改动。
4. **全程离线可用**（车库/赛场/无信号）；设计文件不出内网、无账号无后端。
5. **输入生态**：KiCad 工程、嘉立创下单双 CSV、iBOM pcbdata.json，三种来源都要吃。

## 2. 路线重判（新约束下的 A/B/C）

- **结论：主线仍是 B（自建轻量 PWA + jlc-kicad-bridge 解析层），且新约束让它更成立。**
- 理由更新：
  - 语音识别暂缓后，v1 的交互面收敛为"卡片 + 点位图 + 三按钮 + TTS"，全是自研 UI。iBOM 能复用的只剩渲染，而它是"地图中心"不是"卡片中心"，魔改两头不靠——**A 从"并行快验原型"降级为转换器的一种输入格式（pcbdata.json），不再单独出原型**。初版"一周魔改 iBOM 快验三疑点"的计划取消：疑点中的 wasm 关键词识别随 ASR 暂缓消失，TTS 与大按钮手感在 M2 直接真机验证，验证成本归零。
  - C（微信小程序 + 同传插件）不变，后置 v2+：同传插件本是给 ASR 用的，ASR 暂缓后 C 的唯一优势暂时消失。

## 3. 总体架构

```
PC（设计所在机器）                      手机（焊接桌边）
┌─────────────────────┐    LAN/QR    ┌──────────────────────┐
│ bom2task 转换器(Python) │ ──────────▶ │ 焊接助手 PWA（全离线）     │
│ 三格式 → 焊接任务JSON    │  扫码直达    │ 排序→标定→焊接循环→收尾    │
│ --serve 局域网一键推送   │  或传文件    │ IndexedDB 断点续焊        │
└─────────────────────┘             └──────────────────────┘
```

- PWA 托管 GitHub Pages（HTTPS 才能 Service Worker / WakeLock），装一次、之后全离线。
- **传输主路径**：`python bom2task.py 板子.kicad_pcb --serve` → 屏幕出二维码（带随机路径 token 的局域网 URL）→ 手机扫码 → PWA 接管任务并入库。网络载体随意：家里 WiFi，或"手机热点 + 电脑加入"（赛场/实验室最稳）。
- **兜底路径**：STJ 文件经 QQ 文件传输助手发到手机，PWA"导入文件"。

## 4. 数据契约：焊接任务 JSON v1（全项目第一块基石）

```json
{
  "format": "solder-task-json", "version": 1,
  "meta": {
    "project": "...", "source": "kicad|jlc-csv|ibom-pcbdata",
    "board": {"width_mm": 60, "height_mm": 40, "outline": [[x,y],...]},
    "landmarks": [{"ref": "J2", "speak": "Type-C 口", "x_mm":..., "y_mm":...}]
  },
  "sides": ["top"],
  "groups": [
    {"gid": "g0", "footprint": "0603-R", "value": "10k", "value_speak": "10千欧",
     "footprint_speak": "0603 电阻", "kind": "r", "polarity": false,
     "qty": 7, "refdes": ["R5","R12"]}
  ],
  "placements": [
    {"pid": 0, "gid": "g0", "ref": "R5", "side": "top",
     "x_mm": 12.5, "y_mm": 8.0, "rot": 90, "bbox_mm": [1.6, 0.8]}
  ],
  "group_order_default": ["g0", "g1", ...]
}
```

关键决定：

- 坐标：mm、y 向下、原点 = 板框左上（与 KiCad 屏幕系一致，换算最少）。
- **groups = 袋子（菜名），placements = 点位**。顺序只存 group 序；组内 placement 序由手机端按蛇形扫描现算，单一事实源，PC/手机不打架。
- **所有播报文案 PC 端预计算**（value_speak / footprint_speak / 地标 speak）：手机端零"读值智能"；跨 TTS 引擎读音问题（"10K"读成什么）在数据层修正，不碰代码。
- **保真度三档**：KiCad（板框 + 焊盘形状）> pcbdata.json（板框 + bbox）> 嘉立创双 CSV（点 + bbox，板框由器件外推）。地图 UI 按档降级，不缺失功能。

## 5. 手机端 UI 与交互（核心区，定死）

布局（竖屏）：

```
┌──────────────────────────────────┐
│ 进度 ▓▓▓░░ 17/32            ⚙    │
│ ┌──────────────────┐ ┌────────┐ │
│ │       10k        │ │ 点位图   │ │  ← 上方大区域 ~60%屏高
│ │   0603 电阻       │ │ 缩略图   │ │    卡片为主；点缩略图全屏
│ │  板子右上 · 靠Type-C │ │        │ │
│ │   第5/32      ⚠极性│ │        │ │
│ └──────────────────┘ └────────┘ │
├──────────────────────────────────┤
│ [上一个]  [重新播报]  [    完成    ] │  ← 下方控制区，高度≥屏高1/8
│   25%        25%          50%    │
└──────────────────────────────────┘
```

按钮语义（定死）：

| 操作 | 语义 |
|---|---|
| 完成（点） | 标记 done + 推进 + 播报下一颗；最后一颗 → 收尾清单 |
| 上一个（点） | 回到上一颗、保留其状态（返工场景：重焊后按完成即可） |
| 上一个（长按 600ms，震动确认） | 回退并撤销 done（按错场景） |
| 重新播报（点） | 重读当前颗 |
| 卡片上滑 | 不标记跳过（defer），留给收尾清单兜底 |
| 缩略图点击 | 点位图全屏展开，再点返回 |

点位图：Canvas 画板框 + 器件 bbox（淡灰底图），done 绿色淡显、当前脉冲高亮（DOM 高亮点 + CSS 动画，Canvas 保持静态省电）、批量组琥珀色。视角自动跟随当前器件（缓动），双击回全景，支持捏合缩放平移。整图带标定后的全局旋转。WakeLock 常亮 + 全屏。

## 6. TTS 播报（保留项）

- 引擎：Web Speech `speechSynthesis`（系统 TTS）。安卓离线可用（系统语音包）；iOS 需首次手势解锁——"开始焊接"按钮即解锁点。语速默认 0.9×，可调。
- 播报时机：**推进即播**（手还在收烙铁，话已经说完），模板："{序号}。{封装类型}，{值}，板子{方位}，靠{地标}。"批量组整组只播一次，之后每颗短提示音 + 震动，剩 3 / 剩 1 里程碑口播。
- 文案全部来自 STJ 预计算字段；utterance 在进入该 group 时预热，按下时零延迟。
- TTS 完全不可用（罕见）→ 提示音 + 视觉兜底，功能不瘫。

## 7. 朝向标定（"左上角"成立的前提）

- 开焊前一步：屏幕显示板框 + 自动选的地标（板上最大的边接插件/大件，取 3 个），用户把**手机**转成与桌面板子一致的方向（或点 0/90/180/270 旋转钮）→ ✓ 锁定。任务级记忆，二次开工免标。未标定前只报"图纸方位"，不报左右。
- Android：全屏 + `orientation.lock('portrait')`；iOS 锁不了 → 监听系统旋转让全局旋转角做确定性补偿。
- 翻面（双面板第二面）：提示"左右翻还是上下翻"，配地标确认；地图切镜像视图，方位词自动跟随镜像。中途翻面必须重标。
- 方位播报 = 九宫格（左上/中/右下…）+ 最近地标增强（"靠 Type-C"）。地标式描述天然抗旋转，与标定互补。

## 8. 焊接顺序规划（报菜名）

- **开焊前 30 秒"按袋子点菜"**：屏幕按默认顺序列出所有 group 芯片，用户按桌上元件袋从上到下依次点选 → 得到取料序（点错可撤销芯片）；或直接"用默认顺序"。
- 默认序规则（PC 端）：工艺优先级排 group——先小后大、先矮后高、贴片先于插件、单面焊完再另一面。组内由手机端蛇形扫描（y 分带、x 蛇形），烙铁走线最短。
- 取料序与工艺约束打架时：**v1 以取料序为准**（报菜名的本意），工艺规则只作为默认序初排；"插件统一放最后"之类开关留 v2。

## 9. 批量、返工、收尾、双面

- **批量模式**：进入大组自动提示"10 颗 100nF 一起焊？"——点位图同时亮全部同组焊点，完成一颗灭一颗、下一颗脉冲；卡片显示"第 3/10 颗"。
- **返工**：上一个 → 重焊 → 完成（重新标记）；误触用长按上一个撤销。
- **收尾清单**：最后一颗完成后列出全部未 done（含上滑跳过的）→ "开始补焊"复用同一循环只跑欠账 → 全清后总结（总数/耗时/双面进度）。
- **双面板**：第一面收尾 → "翻面继续" → 翻面标定 → 第二面。
- **断点续焊**：每步持久化（IndexedDB），闪退/杀进程后从"第 17 颗，10k，右上"继续；首页任务列表支持多板并行，各带进度条。

## 10. PC 端转换器 bom2task

- 输入三格式：
  1. KiCad `.kicad_pcb`（v6+，S 表达式直解，含 edge.cuts 板框与焊盘形状）；
  2. 嘉立创 BOM CSV + 坐标 CSV（表头嗅探，兼容标准版/专业版列名变体）；
  3. iBOM `pcbdata.json`（现成生态直接接上）。
- 值归一化：4k7 / 10KΩ / 10000 → 10k；104 → 100nF（双写展示）；m/M 大小写敏感。分组键 = (规范值, 封装)。极性标记（LED/二极管/电解/IC pin1）由 refdes + 封装推断。
- 安装孔、基准点、机械件默认剔除，JSON 里可放开。
- 输出 STJ + `--serve` 二维码推送。依赖：仅标准库 + qrcode。

## 11. 技术栈与仓库

```
mobile-bom-assistant/
├─ converter/   Python：bom2task（解析/归一化/分组/默认序/speak预计算/--serve）
│  └─ tests/    三格式 fixture + 值归一化单测

│  ├─ src/{loader,planner,runner,boardmap,speaker,store}/
```

- 关键模块：**command dispatcher**（唯一指令入口：完成/上一个/播报/跳过…——ASR 日后只需向它发同样指令）；speaker（TTS 封装 + utterance 预热）；boardmap（Canvas + 标定旋转）；store（IndexedDB）。
- 开工第一件事：git init 本目录 + 冻结 STJ v1。
