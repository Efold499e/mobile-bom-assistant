## 0. 一句话定位

把一块板的焊接变成一条按取料顺序排好的流水线。手机一次只干一件事：**看当前件 → 焊 → 按大按钮**。耳朵听播报，眼睛只看卡片和板子，双手不离镊子和烙铁。

## 1. 硬约束与设计原则

1. **布局定死**：竖屏。上方大区域（约 60% 屏高）= 当前器件卡片 + 点位图；下方控制区固定三个大按钮：完成（主）/ 上一个 / 重新播报。任何新功能都进不了这块区域，只能进全屏层（点位图全屏、收尾清单等）。
2. **按钮可盲点**：一手持镊子时指关节能准确点中——「完成」占控制区一半宽、按钮高度 ≥ 屏高 1/8、按下有震动 + 视觉反馈、按钮间隙 ≥ 10dp 且热区超出视觉边界（容错）。
3. **TTS 是主信息通道**；语音识别整体暂缓（不做 ASR、不做唤醒词），控制全靠按钮 + 手势。但所有操作收口到唯一的 **command dispatcher**，日后接 ASR 只是多一个指令来源，UI 零改动。
4. **全程离线可用**（车库/赛场/无信号）；设计文件不出内网，无账号、无后端、无统计。
5. **报菜名优先**：焊接顺序跟着实际取料顺序（元件袋/料盘摆放顺序）走，工艺规则只做默认序。
6. **一次只显示一颗**：小屏渐进展示，不堆全表；全量信息在点位图全屏和收尾清单里。

## 2. 核心循环（产品的心脏）

### 2.1 状态模型

- 任务 = 有序**单元**队列：group（= 元件袋/菜名）按报菜名序展开，组内单元按蛇形扫描序（见 §8）。
- 单元状态 ∈ {**待焊 / 已完成 / 已跳过**}。
- 指针 = 当前单元，初始指向队列中第一个「待焊」单元。

### 2.2 操作语义（定死）

| 操作 | 触发方式 | 效果 |
|---|---|---|
| **完成** | 点主按钮（v1.5 起蓝牙翻页器等效） | 当前单元 → 已完成；指针跳到其后第一个「待焊」；播报下一颗（批量组按 §9 规则）；无待焊 → 收尾清单 |
| **上一个（短按）** | 点 | 指针 -1（返工场景）：状态全部不变，重焊后再按「完成」即重新标记。已在队首则无效 + 短震动 |
| **上一个（长按 600ms）** | 按住，二次震动确认 | 指针 -1，且该单元状态清回「待焊」（撤销误按的已完成） |
| **重新播报** | 点按钮，或点卡片 | 完整重读当前单元 |
| **跳过** | 卡片上滑 | 当前单元 → 已跳过；指针 = 下一个待焊；留给收尾清单兜底，不丢 |

返工走查：第 5 颗焊歪了 → 短按「上一个」回到第 5 颗（状态仍是已完成）→ 重焊 → 按「完成」→ 指针跳到第 6 颗继续。误按完成 → 长按「上一个」→ 第 5 颗清回待焊且指针在其上。

### 2.3 手势与兜底

- 手势只有两个：卡片上滑 = 跳过、点缩略图 = 点位图全屏。跳过没有按钮对应（守住三按钮约束），且跳过项会在收尾清单重现，误滑可救。
- 所有反馈双通道：视觉 + 震动。TTS 失效时功能不瘫（§6）。

## 3. 总体架构与传输（v3 关键修正之一）

```
PC（设计所在机器）                          手机（焊接桌边）
┌────────────────────────┐   传文件（QQ传输助手/  ┌───────────────────────────┐
│ bom2task 转换器(Python)  │   数据线/网盘，随意）   │ 焊接助手 PWA（HTTPS 托管，装一次） │
│ 三格式 → 板子.stj.json    │ ──────────────────▶ │ 导入 → 报菜名 → 标定 → 焊接循环  │
│ 纯标准库，无服务          │                      │ → 收尾；IndexedDB 断点续焊       │
└────────────────────────┘                      └───────────────────────────┘
```

- **传输主路径 = 文件导入，v1 唯一正式路径**：PC 上 `python bom2task.py 板子.kicad_pcb -o 板子.stj.json` → 文件随便怎么传到手机 → PWA 首页「导入任务」选文件（另备「粘贴 JSON」应急入口）→ 校验展示统计 → 入库 IndexedDB。文件导入不依赖网络形态、不受浏览器安全策略限制，且砍掉转换器的全部服务端代码。
- **为什么砍掉 v2 的「扫码局域网直达」**：HTTPS PWA 里抓局域网 HTTP 资源会被混合内容 / 私有网络访问策略拦截；若让 PWA 直接从局域网 HTTP 加载，则丢 Service Worker（离线）和 WakeLock（常亮）——两者都是焊接场景刚需，且局域网源的 IndexedDB 与托管源分库，任务数据会分裂在两个 origin。三条硬约束全受伤，故 v1 不做；「--serve 局域网模式」降级为 v1.5 可选实验（裸 HTTP、接受无常亮的临时场景）。
- PWA 托管：任意 HTTPS 静态托管（GitHub Pages / Netlify / Cloudflare Pages；想仓库私有就用后两者）。首次联网装好，之后全离线。

## 4. 数据契约：焊接任务 JSON（STJ v1，全项目第一块基石）

```json
{
  "format": "solder-task-json",
  "version": 1,
  "meta": {
    "project": "power-board",
    "source": "kicad",
    "created_at": "2026-10-08T21:00:00+08:00",
    "board": { "width_mm": 60.0, "height_mm": 40.0,
               "outline": [[0,0],[60,0],[60,40],[0,40]] },
    "landmarks": [
      { "ref": "J2", "speak": "Type-C 座", "x_mm": 3.0, "y_mm": 20.0 }
    ]
  },
  "sides": ["top"],
  "groups": [
    { "gid": "g0", "kind": "r",
      "footprint": "0603", "footprint_speak": "0603 电阻",
      "value": "10k", "value_speak": "10千欧",
      "polarity": false, "qty": 7, "refdes": ["R5","R12","R13"] }
  ],
  "placements": [
    { "pid": 0, "gid": "g0", "ref": "R5", "side": "top",
      "x_mm": 12.5, "y_mm": 8.0, "rot_deg": 90, "bbox_mm": [1.6, 0.8] }
  ],
  "group_order_default": ["g0", "g1"]
}
```

关键决定：

- **groups = 袋子（菜名），placements = 点位**。分组键 = (kind, 规范化封装, 规范化值)。顺序只存 group 序；组内 placement 序由手机端蛇形扫描现算——单一事实源，PC 与手机不打架。
- **语言原子 PC 端预计算**（value_speak / footprint_speak / 地标 speak）：跨 TTS 引擎的读音问题（"10K"读成什么、"104"要不要念"一百零四"）在数据层修正，手机端零"读值智能"。方位词依赖开工时的朝向标定，由手机端用 x/y 纯算术现组句。
- **坐标 canonical**：mm、原点 = 板框左上、y 向下。各解析器负责变换到该系（嘉立创坐标 CSV 是左下原点 y 向上，必须翻转）。
- **双面坐标陷阱（写进解析器测试）**：底面器件坐标一律存**顶视图坐标** + `side:"bottom"`，不做镜像；镜像只发生在手机端渲染底面视图时。这样翻面标定才成立。
- **保真度三档只影响板框**：KiCad（edge.cuts 多边形）> pcbdata.json（自带 outline）> 嘉立创双 CSV（placements 外接框 + 5mm 外推）。器件几何 v1 统一画 bbox 矩形，焊盘形状留后续版本。
- Loader 校验：format/version 检查、必填字段检查、未知字段忽略（向前兼容）；导入时展示统计（N 颗 / M 组 / 极性 K 颗 / 来源）供人工核对。

## 5. 手机端 UI（布局与规格，定死）

竖屏布局：

```
┌──────────────────────────────────┐
│ ▓▓▓▓▓░░░░░░░░  17/32         ⚙   │ ← 细进度条 + 设置
│ ┌─────────────────────┬────────┐ │
│ │       10k           │ 点位图   │ │
│ │   0603 电阻          │ 缩略图   │ │ ← 上方大区域 ~60% 屏高
│ │  板子右上 · 靠Type-C  │        │ │    卡片占左 2/3，缩略图右 1/3
│ │  第 5/32 颗    ⚠极性  │        │ │    点缩略图 → 全屏地图
│ └─────────────────────┴────────┘ │
├──────────────────────────────────┤
│ [ 上一个 ] [重新播报] [   完成    ] │ ← 下方控制区，高 ≥ 屏高 1/8
│    1fr        1fr       2fr      │
└──────────────────────────────────┘
```

- **卡片**：主行 = 值（超大字号，长值自动缩到下限后省略）；副行 = footprint_speak；第三行 = 方位 + 地标；角标 = 全局序号（第 5/32 颗）、极性警示（⚠极性，v1 只警示不画方向图）。
- **按钮**：完成 = 高对比强调色；按压缩放变色 + 震动 30ms；长按撤销用双段震动确认。标签全中文、字号大。
- **点位图（Canvas）**：板框 + 器件 bbox 底图，静态渲染不进动画循环（省电）；状态着色：待焊淡灰、已完成绿色淡显、已跳过虚线、批量组琥珀色；当前器件用 **DOM 高亮点 + CSS 脉冲动画**叠加（动画不重绘 Canvas）。默认「跟随当前」视角缓动移动，支持捏合缩放/平移、双击回全景、全屏展开。
- **屏幕策略**：进入焊接循环即申请 WakeLock（visibilitychange 时补申请）+ 可选全屏；默认深色主题（焊台/OLED 友好）。
- **全部界面**（8 屏）：首页任务库 / 导入 / 报菜名排序 / 朝向标定 / 焊接循环 / 收尾清单 / 总结 / 设置。焊接循环占产品价值的 90%。
- 首次使用三步：① 联网装 PWA 到主屏 → ② 设置里点「TTS 体检」（提示安装系统中文离线语音包）→ ③ 导入任务开焊。首页内置一块**演示任务**（12 颗，含批量组/极性/双面样例），新手机零文件即可试全流程，也是 TTS 手势解锁的入口。

## 6. TTS 播报（保留项）

- 引擎：Web Speech `speechSynthesis`（系统 TTS）。安卓装中文离线语音包后全程离线；iOS 需首次用户手势解锁——「开始焊接」按钮即解锁点。默认语速 0.9×，设置可调 0.7–1.2×。
- **推进即播**（手还在收烙铁，下一颗的信息已经说完）。播报前 `cancel()` 防排队积压；utterance 在进入该 group 时预构建，按下「完成」零延迟出声。`voiceschanged` 异步就绪处理。
- 句模板（文案原子来自 STJ，方位词设备端现算）：
  - 普通颗：「第 5 颗，共 32 颗。0603 电阻，10 千欧，板子右上，靠 Type-C 座。」（无地标时省略后半句；极性件追加「注意极性」）
  - 批量组开组：「下一组，10 颗 100 纳法，位置都亮出来了，一起焊。」
  - 批量组内：提示音 + 短震动代替整句；剩 3 颗、剩 1 颗里程碑口播。
  - 收尾：「全部播完了，进入收尾清单。」补焊完成：「收工。共 32 颗，用时 47 分钟。」
- TTS 完全不可用（极罕见）：WebAudio 提示音 + 震动 + 卡片视觉兜底，流程照跑。

## 7. 朝向标定（「左上角」成立的前提）

- 开焊前一步：屏幕显示板框 + 自动选的地标（取板上最大的接插件/大件最多 3 个，STJ 预置 speak 名），用户把**手机**转成与桌面板子同向，或点 0°/90°/180°/270° 旋转钮对齐 → ✓ 锁定。旋转角随任务持久化，二次开工免标。
- 未标定前只报「图纸方位」，不报左右——宁可少说，不说错的。
- 安卓：全屏 + `orientation.lock('portrait')`；iOS 锁不了 → 监听旋转让全局旋转角做确定性补偿。v1 以安卓为主战场。
- **方位播报 = 九宫格**（左上/正上/右上/…/右下，按板框三分线）+ 最近地标增强（「靠 Type-C」）。地标式描述天然抗旋转，与标定互补。
- 翻面（双面板）：提示「左右翻还是上下翻」，配地标确认；地图切镜像视图，九宫格词自动跟随镜像。中途翻面必须重标。

## 8. 焊接顺序规划（报菜名）

- **开焊前 30 秒「按袋子点菜」**：屏幕按默认序列出所有 group 芯片（值 + 数量 + 封装），用户照桌上元件袋从上到下依次点选 → 点选序即取料序（点错点一下取消）；或一键「用默认顺序」。不做拖拽。
- **默认序（PC 端预排）**：工艺规则排 group——先小后大、先矮后高、贴片先于插件、单面焊完再另一面。
- **组内序（手机端现算）**：蛇形扫描——按 y 分带（带高 ≈ 中位 bbox 高 × 1.5），带内 x 蛇形走向，烙铁走线最短。
- 冲突原则：**v1 以取料序为准**（报菜名的本意就是跟着袋子走），工艺规则只生成默认序；「插件统一放最后」等开关留 v2。

## 9. 批量、返工、收尾、双面、断点

- **批量模式**：进入 qty ≥ 阈值（默认 4，可关）的组时询问「10 颗 100nF 一起焊？」→ 同意则点位图同时亮全组焊点，每按一次「完成」短提示音 + 震动、灭一颗、卡片显示「第 3/10 颗」；拒绝则逐颗完整播报。
- **返工**：见 §2.2，短按回退 + 重焊 + 完成；误按完成用长按撤销。
- **收尾清单**：最后一颗完成后列出全部未完成（含跳过项，带点位标记）→「开始补焊」以这些单元建临时队列复用同一循环 → 全清后总结屏（总颗数 / 用时 / 各面完成度）。说了「好了」不等于真焊好，但收尾清单保证**没有漏掉的**。
- **双面板**：第一面收尾 →「翻面继续」→ 翻面方向确认 + 重标定 → 第二面。单面任务无此步。
- **断点续焊**：每次操作后原子写 IndexedDB（状态 + 时间戳）；杀进程/闪退重开，任务卡显示「焊到第 17/32」，进入即恢复指针、标定、模式。首页支持多板并行，各带进度条；支持重置进度、导出 STJ、删除任务。

## 10. PC 端转换器 bom2task（纯 Python 标准库）

| 输入 | 板框来源 | 备注 |
|---|---|---|
| KiCad `.kicad_pcb`（v6+） | edge.cuts 多段线取最大外轮廓 | S 表达式直解，不依赖 kicad-cli |
| 嘉立创 BOM CSV + 坐标 CSV | placements 外接框 + 5mm 外推 | 表头嗅探兼容标准版/专业版列名；坐标左下原点 y 向上 → 翻转到 canonical |
| iBOM `pcbdata.json` | 自带 outline | 现成生态直接接入 |

- 值归一化：4k7 / 10KΩ / 10000 → 10k；104 → 100nF（卡片可双写「104」）；2R2 → 2.2Ω、0R → 0Ω 跳线；m/M 大小写敏感（毫/兆）；单位按 refdes 前缀推断（R→Ω、C→F、L→H）。极性件（LED/二极管/电解/IC pin1）由 refdes + 封装关键词推断。
- 剔除：安装孔、基准点、机械件默认剔除（STJ 可放开）；speak 原子全部在此生成（中文单位：皮法/纳法/微法/欧/毫亨…）。
- 附带 `--check` 统计输出（颗数/组数/极性数/异常值打印），开工前对着元件袋数数做人工 sanity check。
- 依赖：仅标准库（csv/json/re/argparse）。零服务端代码（--serve 是 v1.5 实验项）。

## 11. 技术栈与仓库

```
mobile-bom-assistant/
├─ converter/        Python：bom2task（解析/归一化/分组/默认序/speak/--check）
│  └─ tests/         三格式 fixture + 值归一化 + 底面坐标陷阱单测
├─ webapp/           Vite + Preact + TypeScript + vite-plugin-pwa
│  ├─ src/{loader, planner, runner, boardmap, speaker, store, dispatcher}/
│  └─ public/demo/   内置演示任务 STJ
└─ docs/
```

- 关键模块：**command dispatcher**（唯一指令入口：完成/上一个/播报/跳过/撤销…——ASR、蓝牙键日后只是新指令来源）；speaker（TTS 封装 + utterance 预热 + 提示音兜底）；boardmap（Canvas + 标定旋转 + 跟随）；store（IndexedDB 原子持久化）；loader（STJ 校验）。
- 质量底线：converter 金样测试（fixture → 期望 STJ 全文比对）；webapp 用浏览器自动化对演示任务跑核心循环冒烟（推进 3 颗 → 回退 → 刷新验证持久化 → 跑完 → 收尾清单）。
- 开工第一件事：git init 本目录 + 冻结 STJ v1。

## 12. 里程碑（开工后，业余时间口径，风险前置排序）

| M3 | 点位图（Canvas/跟随/全屏）+ 朝向标定 + 翻面镜像 + 批量高亮 | 3 天 |

合计 ≈ 2–2.5 周到实战 v1。**M1 末就真机暴露最大风险（TTS 音色与按钮手感）**——这是 v3 把 webapp 排在转换器前面的原因：M0 有演示任务后两条线即可独立推进，风险线先行。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 各家安卓 TTS 音色/中文数字断句参差 | speak 原子在数据层可调；M1 真机最早验证；设置内语速 + TTS 体检 |
| iOS Safari 限制（旋屏锁不了、无震动、语音手势） | v1 安卓主战场；iOS 尽力（手势解锁 + 旋转补偿），不承诺 |
| 嘉立创 CSV 列名/坐标系漂移 | 表头嗅探 + 真实文件 fixture 持续回填；底面坐标陷阱进单测 |
| 解析错误导致静默错排 | --check 统计 + 开工前对袋子人工数数核对；loader 导入统计二次确认 |
| 密集板点位图糊 | 默认跟随缩放；缩略图只画点，细节进全屏 |
| 亮屏耗电 | 全程离线不启无线电；静态 Canvas + CSS 动画；深色 OLED；长任务提示插电 |
| 焊接中被打断（说话/找料） | 指针语义线性无副作用，「重新播报」一键接上 |

## 14. 暂缓项的归所（后续版本）

- **v1.5**：蓝牙翻页器——静音 `<audio>` 占位持有 MediaSession，¥10 媒体翻页器的「下一曲」映射为「完成」，息屏可用，比 ASR 便宜可靠；极性方向图示（pin1 圆点/负极丝印）；`--serve` 局域网模式实验（裸 HTTP，接受无常亮）。
- **v2**：语音识别回归（dispatcher 已留位；届时重估 Web Speech / wasm 关键词 / 云 ASR）；元件墙拍照 → VLM 自动报菜名；焊后 CV 复查漏焊。
- **v3+**：微信小程序化（分享传播 + 同传插件）。
